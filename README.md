# Dead Pixel — Profile Site

## Folder structure

```
website/
├── index.html        Main page (do not put JS/CSS logic directly in here)
├── styles/            All CSS lives here
│   └── style.css
├── src/                All TypeScript source lives here
│   └── main.ts
├── assets/             Images/icons go here (empty for now)
├── dist/                Compiled JS output — generated by the build, not committed
├── tsconfig.json
├── package.json
└── .gitignore
```

Future JS, CSS, or other code should go in its own folder the same way
(`styles/`, `src/`, `assets/`) rather than mixed into `index.html`.

## What's interactive

- **Terminal hero** — prints an intro and the command list automatically on
  load. Visitors can type `about`, `make`, `skills`, `contact`, `help`, or
  `clear` into the input and press Enter.
- **Scroll-spy nav** — the top nav highlights whichever section is currently
  in view.
- **Mobile nav** — collapses into a toggle menu under ~640px wide.
- **Reveal-on-scroll** — each section fades in once, the first time it comes
  into view.
- **Scroll progress bar** — thin bar at the very top fills as you scroll.
- **Skill tags** — tap to toggle a highlighted state (wired up for future
  project filtering).
- **Copy button** — copies the contact email to the clipboard.
- **Expandable project cards** — any element with class `project-card`
  toggles an `is-expanded` state on click/Enter/Space. Ready for when real
  projects are added to the `#projectGrid` grid in `index.html`.

## How the TypeScript build works

`src/main.ts` is written in TypeScript. It's compiled to plain JavaScript
in `dist/main.js`, which `index.html` loads. You never edit `dist/` by
hand — it's regenerated every build.

**`dist/main.js` is committed to the repo**, not gitignored. That means
the site works as plain static files with zero build configuration on
Cloudflare's side — no risk of the script silently failing to load
because a build step didn't run. Whenever `src/main.ts` changes, the
compiled `dist/main.js` handed to you alongside it is already up to
date — just commit both together.

## Deploying with Cloudflare Pages

No build command needed. In Cloudflare Pages project settings:

- **Framework preset:** None
- **Build command:** (leave empty)
- **Build output directory:** `/` (the project root)

Cloudflare just serves the repo's files as-is. Every push to GitHub
triggers a redeploy automatically.
